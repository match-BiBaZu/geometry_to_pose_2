# Chute Pose Analysis Pipeline — Baseline Usage

Four tools, meant to run in this order:

```
ChutePoseAnalysis.m  --->  chute_drop_batch.py  --->  PoseAnalysisMaster.m
                                    |
                                    v
                        plot_pose_probabilities.m
```

1. **ChutePoseAnalysis.m** — geometric prediction (MATLAB, no sim, no physics)
2. **chute_drop_batch.py** — Monte-Carlo physics validation (PyBullet) against #1
3. **plot_pose_probabilities.m** — quick per-condition bar chart, sim vs. geometry
4. **PoseAnalysisMaster.m** — pooled scatter/fit report across all conditions

Standard angle grid used throughout this README:

- **Roll**: `15, 25, 35, 45` deg
- **Pitch**: `15, 17.5, 20` deg

---

## 1. ChutePoseAnalysis.m

**What it does:** For each STL part in a folder, at every (roll, pitch) combo, enumerates every way the part can physically come to rest in the chute (floor + wall contact), scores each resting pose's likelihood six different ways (CSA_B/A/N, CRSA_B/A/N), and writes out summaries + figures.

**How to run:**
```matlab
ChutePoseAnalysis
```
It's fully GUI-driven — no arguments. You'll be walked through:
1. A folder picker — select the folder containing your `.stl` files.
2. Roll input — choose **Range**, then enter Start=`15`, End=`45`, Increment=`10`.
3. Pitch input — choose **Range**, then enter Start=`15`, End=`20`, Increment=`2.5`.

It then loops over every STL × every roll × every pitch combination automatically.

**What it returns:** Inside `<partsFolder>/results/<PartName>/<PartName>_<roll>R_<pitch>P/`, for every condition:
- `..._MASTER_summary.txt` — the main output: one row per stable pose with all six probability scores, moment-arm ratios, and stability notes.
- `..._GEOMETRIC_summary.txt` — every candidate pose before stability filtering (used later for symmetric-pose matching).
- `<condition>.pdf` — per-pose figures (part-in-chute + solid-angle geometry).
- `critical value metrics/` — wall/floor transition-ratio scatter PDFs.

This step must run first — everything downstream reads its output folder structure.

---

## 2. chute_drop_batch.py

**What it does:** Runs randomized PyBullet drop-physics trials into a tilted chute for each condition, matches each trial's final resting orientation against the pose catalog from step 1, and tallies an empirical (simulated) pose-frequency distribution to compare against the geometric predictions.

**Files needed (and where they come from):**
- **STL part meshes** (`Df4a.stl`, `Ql4i.stl`, `Rk2i.stl`, etc.) — your own CAD exports. Point `--stl-folder` at the folder containing them.
- **Chute mesh** (`chute.obj`) — your own chute geometry, exported as `.obj`. Must be concave-capable (`--chute-concave`) if it isn't a simple convex shape.
- **`results/` folder** — produced by step 1 (`ChutePoseAnalysis.m`). Point `--results-root` at wherever that landed (or `--parts-folder` if `results/` sits directly inside it, per the default). This is what supplies each condition's `_MASTER_summary.txt` / `_GEOMETRIC_summary.txt` for pose matching — the batch script has nothing to compare against without it.
- Everything else (trials CSVs, sim summaries, `combined_summary.csv`) is generated by this script itself into `--out-dir`.

This is normally run from two cells in a Jupyter notebook rather than the command line — set `NOTEBOOK_ARGV` to your flag list, then call `main()`. Both cells below use `--drop-height`/`--chute-z-lift` scaled up and near-zero friction / high restitution, i.e. tuned for a bouncy, near-frictionless drop test rather than a realistic PTFE surface — adjust those to your actual material properties.

## 3. plot_pose_probabilities.m

**What it does:** Draws a grouped bar chart per (part, roll, pitch) condition — experimental (simulated) frequency vs. one or more algorithmic (geometric) columns — from the CSV(s) produced by step 2.

**Files needed:**
- `combined_summary.csv` (or a single `*_sim_summary.csv`) — produced by `chute_drop_batch.py` (step 2). No other input required.

**How to run (baseline):**
```matlab
plot_pose_probabilities('combined_summary.csv', ...
    'GeomColumn', {'CSA_B'}, ...
    'IncludeUnmatched', false, ...
    'ApplyModifier', true, ...
    'SortBy', 'sim_freq_pct')
```
- `'GeomColumn', {'CSA_B'}` — compares experimental frequency against the CSA_B algorithm column (transitioning poses zeroed, remaining renormalized). Pass a cell array of multiple names to plot several algorithm variants side by side in the same figure.
- `'IncludeUnmatched', false` — drops the pose_id == -1 "unmatched" bar (trials whose settled orientation didn't match any catalog pose) instead of showing it forced to 0%.
- `'ApplyModifier', true` — applies the default post-hoc weighting modifier (`mod_i = 1/avg(ratio_wall, ratio_floor)`) to the algorithmic column before renormalizing.
- `'SortBy', 'sim_freq_pct'` — orders poses by experimental frequency (descending) instead of by pose ID, so the biggest discrepancies/most common poses show up first.

**What it returns:** One MATLAB figure per (part, roll, pitch) condition found in the file — a bar chart of poses on the X-axis, experimental vs. CSA_B (modified) frequency (%) on the Y-axis, with correlation/RMSE stats annotated on the figure by default. Add `'SaveDir', 'figs'` to save each as a PNG instead of just displaying.

## 4. PoseAnalysisMaster.m

**What it does:** Pools every part/condition/pose together and produces one scatter-and-best-fit-line figure per algorithm variant (6 total), plus a text report with overall and per-part accuracy stats — the "how good is each algorithm, across everything" summary.

**Files needed:**
- `combined_summary.csv` — produced by `chute_drop_batch.py` (step 2). No angle-grid input needed here; it reads whatever conditions are already in the file.

**How to run (baseline):**
```matlab
PoseAnalysisMaster('combined_summary.csv', 'ApplyModifier', true)
```
- `'ApplyModifier', true` — applies the same default post-hoc modifier as above (`mod_i = 1/avg(ratio_wall, ratio_floor)`) to all six `geom_*_pct` columns, independently, within each (part, roll, pitch) condition, before pooling everything into the scatter/fit stats.

**What it returns:** Saved to `OutputDir` (default: a `PoseAnalysisMaster_out` folder next to the CSV):
- `PoseAnalysisMaster_ScatterFit_<AlgoName>.png` × 6 — one scatter plot per algorithm (CSA_Dyn, CSA_Stat, CSA_Nan, CRSA_Dyn, CRSA_Stat, CRSA_Nan), algorithm probability vs. experimental probability, points colored by part, with a best-fit line.
- `PoseAnalysisMaster_Report.txt` — MSE, Pearson r, and R² for each algorithm, overall and broken down per part.

This is the tool you'd check to decide which of the six algorithm variants (CSA vs. CRSA, and B/A/N filtering) best matches real drop behavior.
